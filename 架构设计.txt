        server
            commands
                config.js
                    Config.get()：
                        返回 store.config 的深拷贝
                    Config.update(partialConfig)：
                        将 partialConfig 的每个字段合并覆盖到 store.config
                        将 store.config 写入 .agent/config.json
                        返回更新后的 store.config
                workspace.js
                    Workspace.list()：
                        返回 store.workspaces
                    Workspace.add(path)：
                        生成唯一 id
                        创建工作区对象 { id, path, sessions: [] }
                        推入 store.workspaces
                        写入 .agent/workspace.json
                        返回新建的工作区对象
                    Workspace.update(workspaceID, fields)：
                        在 store.workspaces 中找到 id === workspaceID 的项
                        如果 找不到 → 抛错 "工作区不存在"
                        将 fields 合并覆盖到该项
                        写入 .agent/workspace.json
                        返回更新后的工作区对象
                    Workspace.remove(workspaceID)：
                        在 store.workspaces 中找到 id === workspaceID 的项
                        如果 找不到 → 抛错 "工作区不存在"
                        从数组中移除该项（不删本地目录）
                        写入 .agent/workspace.json
                        返回 { ok: true }
                session.js
                    Session.get(sessionID)：
                        如果 store.sessions 中有缓存 → 返回缓存
                        否则：
                            从 .agent/sessions/{sessionID}.json 读取
                            如果 文件不存在 → 抛错 "会话不存在"
                            存入 store.sessions 缓存
                            返回 session 数据
                    Session.create(workspaceID)：
                        在 store.workspaces 中找到对应工作区
                        如果 找不到 → 抛错 "工作区不存在"
                        生成唯一 sessionID
                        创建 session
                            id: sessionID,
                            workspaceID,
                            title: "新对话",
                            lastActiveAt: 当前时间戳,
                            model: store.config.defaultModel,
                            status: "idle",
                            messages: []
                        存入 store.sessions 缓存
                        写入 .agent/sessions/{sessionID}.json
                        在工作区的 sessions 数组中添加 { sessionID, title: "新对话" }
                        写入 .agent/workspace.json
                        返回 session
                    Session.update(sessionID, fields)：
                        session = Session.get(sessionID)
                        将 fields 合并覆盖（只允许 title、model 等配置字段）
                        session.lastActiveAt = 当前时间戳
                        写入 .agent/sessions/{sessionID}.json
                        如果 fields 中有 title：
                            同步更新 store.workspaces 中对应的 session 摘要的 title
                            写入 .agent/workspace.json
                        返回更新后的 session
                    Session.delete(sessionID)：
                        session = Session.get(sessionID)
                        如果 session.status !== "idle"：
                            先调用 Agent.stop(sessionID)
                        关闭该 sessionID 的所有 SSE 连接
                        从 store.sessions 缓存中移除
                        删除 .agent/sessions/{sessionID}.json
                        从 store.workspaces 中对应工作区的 sessions 数组移除
                        写入 .agent/workspace.json
                        返回 { ok: true }
                    Session.listen(sessionID, lastEventID)
                        返回 SSE Stream，并按 lastEventID 补发或发送 resync
                    Session.save(sessionID)
                        保存逻辑
                agent.js
                    Agent.send(sessionID, content)：
                        session = Session.get(sessionID)
                        如果 session.status 是 "running"、"waiting" 或 "retrying"：
                            抛错 "该会话正在执行中"
                        创建 userMessage
                            id: 生成唯一ID,
                            role: "user",
                            content,
                            contentBlocks: [{ id: 生成唯一ID, type: "text", text: content }],
                            timestamp: 当前时间戳
                        推入 session.messages
                        session.status = "running"
                        session.lastActiveAt = 当前时间戳
                        如果 存在 session.rolledBack 就清空
                        SessionWatcher.publish(sessionID, "status", { status: "running" })
                        SessionWatcher.publish(sessionID, "message-start", { message: userMessage })
                        保存 session
                        Agent.run(sessionID)  ← 异步启动，不 await
                        返回 { messageID: userMessage.id }
                    Agent.stop(sessionID)：
                        session = Session.get(sessionID)
                        如果 session.status === "idle"：
                            返回 { ok: true, message: "已经是空闲状态" }
                        打断LLM API请求
                        遍历并拒绝未决策的工具调用
                        终止该 session 下的所有工具运行进程
                        session.status = "idle"
                        SessionWatcher.publish(sessionID, "status", { status: "idle", reason: "stopped" })
                        保存 session
                        返回 { ok: true }
                    Agent.run(sessionID)：
                        未调用工具次数计数=0
                        无限循环
                            turnResult = Turn.run(sessionID, reminder)
                            如果 turnResult.shouldStop → 跳出循环
                            如果 turnResult.hasToolCalls：
                                未调用工具次数计数=0
                                继续循环
                            未调用工具次数计数+1
                            如果计数为1 → 继续循环
                            如果计数为2 → 下一轮加入临时工具提醒后继续循环
                            如果计数为3 → 保留普通回复并跳出循环
                        清理 runtime，设置最终状态并保存 session
                turn.js
                    Turn.run(sessionID, reminder)：
                        Context.build 构建当前轮上下文
                        找到模型对应的已启用供应商
                        发起模型请求；可重试错误无限退避，不限制重试次数
                        Stream.consume 将流写入助手消息
                        保存完整助手消息和 usage
                        收集 tool_call blocks
                        有工具调用时交给 Tool.runAll 并保存 tool message
                        返回 hasToolCalls 和 shouldStop
                stream.js
                    Stream.consume(sessionID, messageID, stream)：
                        将 text、thinking、tool_call 和 usage 流片段写入助手消息
                        每个新 block 生成会话内唯一 id
                        每个 delta 通过 SessionWatcher.publish 反馈，不逐片落盘
                tool.js
                    Tool.runAll(sessionID, toolCalls)：
                        同一轮所有工具完全并行执行
                        permission 为 allow 时执行、deny 时拒绝、ask 时等待 Approval
                        结果按 toolCalls 原顺序组成 tool message
                    Tool.abortAll(sessionID)：
                        并行终止该会话的所有工具进程
                approval.js
                    Approval.once(sessionID, toolCallID)：仅允许当前工具调用
                    Approval.always(sessionID, toolCallID)：允许当前调用并将 permission 保存为 allow
                    Approval.reject(sessionID, toolCallID)：拒绝当前工具调用
                    Approval.wait(sessionID, toolCallID)：最多等待 30 分钟，超时按 reject 处理
                history.js
                    History.rollbackMessage(sessionID, messageID)：
                        截断目标用户消息及后续消息，存入 session.rolledBack
                    History.rollbackBlock(sessionID, blockID)：
                        截断目标 block、同消息后续 blocks 和后续 messages，存入 session.rolledBack
                    History.undo(sessionID)：
                        从 session.rolledBack 恢复最近一次回退并清空临时数据
                context.js
                    Context.build(sessionID, reminder)：构建模型上下文
                    Context.compress(sessionID)：执行上下文压缩
            watchers
                session.js
                    SessionWatcher.publish(sessionID, event, data)：统一分配 eventID、缓存并发送 SSE

            server.js（Elysia框架，直接注册全部路由，不建立 routes 文件夹）
                当 服务器启动时：
                    Config.load() → 从 .agent/config.json 读取内容 → 存入 store.config
                    Workspace.load() → 从 .agent/workspace.json 读取内容 → 存入 store.workspaces
                    在当前文件直接注册路由组：health、config、workspace、session
                    监听端口 4632
                    打印启动日志
                当 收到 GET /health 时：
                    直接返回 200 { status: "ok", version: store.engine.version }
                当 收到 GET /config 时：
                    返回 200 Config.get()
                当 收到 PATCH /config 时：
                    返回 200 Config.update(body)
                当 收到 GET /workspace 时：
                    返回 200 Workspace.list()
                当 收到 POST /workspace 时：
                    返回 201 Workspace.add(body.path)
                当 收到 PATCH /workspace 时：
                    返回 200 Workspace.update(body.workspaceID, body 中除 workspaceID 外的字段)
                当 收到 DELETE /workspace?workspaceID={workspaceID} 时：
                    返回 200 Workspace.remove(query.workspaceID)
                当 收到 GET /session?sessionID={sessionID} 时：
                    返回 200 Session.get(query.sessionID)
                当 收到 POST /session 时：
                    返回 201 Session.create(body.workspaceID)
                当 收到 PATCH /session 时：
                    返回 200 Session.update(body.sessionID, body 中除 sessionID 外的字段)
                当 收到 DELETE /session?sessionID={sessionID} 时：
                    返回 200 Session.delete(query.sessionID)
                当 收到 GET /session/events?sessionID={sessionID} 时：
                    返回 Session.listen(query.sessionID, Last-Event-ID) SSE 长连接
                当 收到 POST /session/send 时：
                    返回 202 Agent.send(body.sessionID, body.content)
                当 收到 POST /session/stop 时：
                    返回 200 Agent.stop(body.sessionID)
                当 收到 POST /session/approval 时：
                    根据 decision 直接调用 Approval.once、Approval.always 或 Approval.reject
                当 收到 POST /session/history 时：
                    根据 action 直接调用 History.rollbackMessage、History.rollbackBlock 或 History.undo
                当 服务器收到未知路由请求时：
                    返回 404 { error: { code: "NOT_FOUND", message: "Not Found" } }
                当 进程收到终止信号时：
                    遍历 store.sessions → Agent.stop → 关闭 session.runtime.listeners → Session.save
                    退出进程

    API
        /health
            GET
                服务状态、版本号
        /config
            GET
                获取所有配置
            PATCH
                修改配置
        /workspace
            GET
                获取工作区列表及其下属 Session 列表
            POST
                添加工作区
                path
            PATCH
                修改工作区定义
                workspaceID、需要修改的字段
            DELETE
                从工作区列表移除工作区
                workspaceID（query）
                不删除本地目录内容
        /session
            GET
                单个 Session 的全部数据
                sessionID（query）
            POST
                创建 Session
                workspaceID
            PATCH
                修改 Session 配置
                sessionID、需要修改的字段
            DELETE
                删除 Session
                sessionID（query）
            /send
                POST
                    发送用户消息并启动执行
                    sessionID、content
                    返回状态，实时内容通过 Session SSE 接收
            /stop
                POST
                    停止 Session 当前执行
                    sessionID
                    终止该会话的API请求与正在进行的工具和工具等待
            /events
                GET
                    订阅 Session 的 SSE 事件
                    sessionID
                    每个事件需要携带递增的 eventID
                    返回文本、推理、工具、审批、任务、usage、上下文和执行状态
            /approval
                POST
                    处理工具权限请求
                    sessionID、toolCallID、decision
                    decision：once、always、reject
            /history
                POST
                    回退工具步骤、回退用户消息或撤销回退
                    sessionID、action、对应目标
                    action：rollback-block、rollback-message、undo
                    rollback-block 提供 blockID
                    rollback-message 提供 messageID
