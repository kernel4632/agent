fix: 自动批准按 roo code 的真实颗粒度做，顺带修掉两个审批漏洞

你指出四类不对。我去读了本机装的 zoo-code（roo code 的分支）源码，
它的设置面板其实是 7 个顶层开关 + 3 个子选项：

  alwaysAllowReadOnly / alwaysAllowWrite / alwaysAllowExecute /
  alwaysAllowMcp / alwaysAllowModeSwitch / alwaysAllowSubtasks /
  alwaysAllowFollowupQuestions
  外加 alwaysAllowReadOnlyOutsideWorkspace /
      alwaysAllowWriteOutsideWorkspace / alwaysAllowWriteProtected

对上我们真有的东西，改成五类：读取 / 写入 / 执行命令 / 使用 MCP / 创建子任务。
它那边的「切换模式」和「追问」我们这里根本不存在（模式是用户在界面上切的，
不是模型自己切的；也没有到点自动选追问答案的机制），所以不设这两个开关——
真加了就是永远不生效的空开关。

改的过程中发现两个真的漏洞，都不是新写的代码，是一直就在的：

1. 子 agent 完全不走审批。delegation.js 建子 agent 时没传 onPermission，
   agent-core 就直接放行。后果是子任务里的读文件和执行命令完全不问用户，
   .agentignore 也拦不住，而且不报任何错——表现只是"某个密钥文件莫名其妙
   被读到了"。现在带着同一个审批回调，回到同一条会话。

2. plan 模式可以借 task 绕过。session.js 把未筛选的工具表交给了 Delegation.build，
   于是 plan 模式下主 agent 自己改不了文件，却能让子任务去改。现在先筛再装 task，
   子 agent 拿到的就是筛过的那张表。

顺带把 todo / finish / ask 归成"本来就不需要批准"：它们是控制循环用的，
既不碰磁盘也不碰外部服务。每次都要问一遍的话用户只会一直点同意，
审批弹窗也就没意义了。

契约和防漂移：
- 类别清单仍然只在 utils/tool-kind.js 一处，由它现算出默认值、文档 schema、界面开关
- openapi.json 的 AutoApprove schema 从这份清单生成
- 新增 5 条检查，每条都用探针确认过会失败：

    plan 借子任务改文件 → 1 fail
    记清单也弹窗      → 1 fail
