# 接口契约

本文是 HTTP API、SSE 事件和错误格式的权威来源。所有字段名遵循 [数据.md](数据.md)。

## 通用规则

- 服务默认监听 `4632` 端口。
- 请求和普通响应使用 JSON。
- 成功时直接返回资源或动作结果，不额外包裹 `data`。
- 失败时返回统一错误对象和正确的 HTTP 状态码。
- API Key 和其他配置原样返回，不进行脱敏。

### 错误格式

```json
{
  "error": {
    "code": "SESSION_NOT_FOUND",
    "message": "会话不存在"
  }
}
```

| HTTP 状态 | code | 使用场景 |
| --- | --- | --- |
| 400 | `INVALID_PARAM` | 缺少参数、格式错误或枚举值无效。 |
| 404 | `WORKSPACE_NOT_FOUND` | 工作区不存在。 |
| 404 | `SESSION_NOT_FOUND` | 会话不存在。 |
| 404 | `PROVIDER_NOT_FOUND` | 当前模型没有可用供应商。 |
| 404 | `TOOL_CALL_NOT_FOUND` | 待批准工具调用不存在或已经结束。 |
| 409 | `SESSION_BUSY` | 会话仍在执行，不能开始新执行或修改历史。 |
| 502 | `PROVIDER_FAILED` | 供应商返回不可重试错误。 |
| 500 | `INTERNAL` | 未归类的服务端错误。 |

## Health

### `GET /health`

`server.js` 中的路由直接读取 `store.engine.version`。健康检查不建立额外指令或路由文件。

响应 `200`：

```json
{
  "status": "ok",
  "version": "0.1.0"
}
```

## Config

### `GET /config`

返回完整配置原值，包括 API Key。

响应 `200`：符合 [数据.md](数据.md) 中的 `config`。

### `PATCH /config`

请求体是要递归合并进当前配置的部分对象。普通对象继续合并，数组和基础值整体替换。

响应 `200`：合并后的完整配置原值。

## Workspace

### `GET /workspace`

返回所有工作区及会话摘要缓存。

响应 `200`：`workspace[]`。

### `POST /workspace`

请求体：

```json
{
  "path": "D:\\projects\\example"
}
```

响应 `201`：新建的 workspace。

### `PATCH /workspace`

请求体包含 `workspaceID` 以及要递归合并到工作区的其他字段。普通对象继续合并，数组和基础值整体替换。

响应 `200`：修改后的 workspace。

### `DELETE /workspace?workspaceID={workspaceID}`

只从工作区列表移除，不删除本地目录内容。

响应 `200`：

```json
{
  "removedID": "workspace_01"
}
```

## Session

### `GET /session?sessionID={sessionID}`

返回一个完整会话。运行时字段不返回。

响应 `200`：持久化 session。

### `POST /session`

请求体：

```json
{
  "workspaceID": "workspace_01"
}
```

响应 `201`：新建的 session。

### `PATCH /session`

请求体包含 `sessionID` 以及要递归合并到会话的其他字段。普通对象继续合并，数组和基础值整体替换。

响应 `200`：修改后的 session。

### `DELETE /session?sessionID={sessionID}`

删除会话文件和工作区中的会话摘要。如果会话正在运行，先停止模型请求、批准等待和工具进程。

响应 `200`：

```json
{
  "removedID": "session_01"
}
```

## Agent

### `POST /session/send`

请求体：

```json
{
  "sessionID": "session_01",
  "content": "分析这个工作区"
}
```

响应 `202`：

```json
{
  "messageID": "message_01"
}
```

实时内容通过该 session 的 SSE 接收。

### `POST /session/stop`

请求体：

```json
{
  "sessionID": "session_01"
}
```

停止模型请求、无限重试的退避等待、所有批准等待和所有工具进程。

响应 `200`：

```json
{
  "status": "idle",
  "reason": "stopped"
}
```

## Approval

### `POST /session/approval`

请求体：

```json
{
  "sessionID": "session_01",
  "toolCallID": "tool_call_01",
  "decision": "once"
}
```

`decision` 只能是 `once`、`always` 或 `reject`。

响应 `200`：

```json
{
  "toolCallID": "tool_call_01",
  "decision": "once"
}
```

## History

### `POST /session/history`

消息回退：

```json
{
  "sessionID": "session_01",
  "action": "rollback-message",
  "messageID": "message_01"
}
```

内容块回退：

```json
{
  "sessionID": "session_01",
  "action": "rollback-block",
  "blockID": "block_01"
}
```

撤销回退：

```json
{
  "sessionID": "session_01",
  "action": "undo"
}
```

回退只影响会话历史，不撤销文件或外部系统变化。

响应 `200`：修改后的完整 session。

## SSE 连接

### `GET /session/events?sessionID={sessionID}`

响应类型是 `text/event-stream`。客户端应先建立 SSE 连接，再调用 `/session/send`。

客户端重连时通过 `Last-Event-ID` 请求补发。服务端从 session 的最近 500 条事件缓冲中补发该 ID 之后的事件。以下情况发送 `resync`：

- 客户端 ID 已不在缓冲区。
- 服务进程重启，运行时事件缓冲已清空。
- 客户端 ID 大于服务端当前 ID。

收到 `resync` 后，客户端调用 `GET /session` 重新取得完整会话。

### SSE 帧

```text
id: 42
event: status
data: {"status":"running"}
```

`eventID` 在每个 session 内递增，不跨 session 比较。

## SSE 事件

| event | data | 触发时机 |
| --- | --- | --- |
| `status` | `{ status, reason? }` | 会话进入 running、waiting、retrying、idle 或 error。reason 可为 completed、stopped、failed。 |
| `message-start` | `{ message }` | 用户、助手或工具消息加入会话。流式助手消息首次创建时发送。 |
| `text-delta` | `{ messageID, blockID, delta }` | 助手文本块追加内容。 |
| `thinking-delta` | `{ messageID, blockID, delta }` | 助手推理块追加内容。 |
| `tool-call-start` | `{ messageID, block }` | 模型开始输出工具调用。 |
| `tool-input-delta` | `{ messageID, blockID, delta }` | 工具输入 JSON 片段到达。 |
| `tool-call-ready` | `{ messageID, block }` | 工具输入解析完成，可以进入权限判断。 |
| `approval-needed` | `{ messageID, block }` | 工具权限为 ask，等待用户决定。 |
| `tool-result` | `{ messageID, block }` | 工具完成、被拒绝或失败。 |
| `api-request` | `{ status, usage? }` | 模型请求开始或完成。status 为 started 或 completed。 |
| `context` | `{ inputTokens, contextLimit, percentage }` | 每轮模型请求前完成上下文构建。 |
| `task` | `{ tasks }` | Agent 更新当前任务列表。任务结构在工具契约设计时补充。 |
| `history` | `{ action, session }` | 完成消息回退、内容块回退或撤销回退。 |
| `error` | `{ code, message, willRetry }` | 模型、工具或内部操作失败。可重试错误的 willRetry 为 true。 |
| `resync` | `{ reason }` | 无法从事件缓冲补齐客户端缺失事件。 |

## 事件发布规则

服务端业务指令修改 session 数据后，显式调用 `SessionWatcher.publish(sessionID, event, data)`。`watchers/session.js` 负责校验事件、分配 `eventID`、写入事件缓冲并发送给 listeners。其他模块不得分配事件 ID、操作事件缓冲、编码或发送 SSE 帧。
