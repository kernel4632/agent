# API 接口

所有接口由 `server.js` 直接注册。当前阶段只提供 Agent 运行必需的接口。

## Health

### `GET /health`

检查后端是否运行。

响应：

```json
{
  "status": "ok"
}
```

## Config

### `GET /config`

返回完整配置，包括原始 key。

```json
{
  "provider": {
    "api": "https://api.openai.com/v1",
    "key": "sk-example",
    "models": ["gpt-5"]
  },
  "tools": [
    {
      "name": "read_file",
      "description": "读取指定路径的文本文件内容。",
      "inputSchema": {
        "type": "object",
        "properties": {
          "path": { "type": "string" }
        },
        "required": ["path"]
      }
    }
  ]
}
```

### `PATCH /config`

把请求体合并到 `store.config` 并保存 `.agent/config.json`。

请求示例：

```json
{
  "provider": {
    "key": "new-key"
  }
}
```

响应为修改后的完整配置。

## Workspace

### `GET /workspace`

返回所有工作区及其会话摘要。

```json
[
  {
    "id": "workspace-1",
    "path": "D:\\project",
    "sessions": [
      {
        "id": "session-1",
        "title": "新对话",
        "lastActiveAt": 1785751200000
      }
    ]
  }
]
```

### `POST /workspace`

添加工作区。

```json
{
  "path": "D:\\project"
}
```

响应为新工作区。

### `DELETE /workspace?id={workspaceId}`

从 `store.workspaces` 移除工作区并保存。不会删除本地目录或会话文件。

响应：

```json
{
  "id": "workspace-1"
}
```

## Session

### `GET /session?id={sessionId}`

返回会话的持久化数据。响应不包含 `processes`、`abortController`、`clients` 和 `textOnlyCount`。

```json
{
  "id": "session-1",
  "status": "idle",
  "messages": [],
  "provider": "openai",
  "model": "gpt-5"
}
```

### `POST /session`

创建会话，并在指定工作区加入会话摘要。

```json
{
  "workspaceId": "workspace-1",
  "provider": "openai",
  "model": "gpt-5"
}
```

响应为新建的完整会话。

### `PATCH /session`

修改会话标题、供应商或模型。

```json
{
  "id": "session-1",
  "title": "分析项目",
  "provider": "openai",
  "model": "gpt-5"
}
```

- `title` 修改工作区中的会话摘要。
- `provider` 和 `model` 修改完整 session。

响应为修改后的完整会话。

### `DELETE /session?id={sessionId}`

如果会话正在运行则先停止，再删除完整会话和工作区中的摘要。

响应：

```json
{
  "id": "session-1"
}
```

## Agent

### `POST /session/send`

添加用户消息并在后台启动 Agent。

```json
{
  "id": "session-1",
  "content": "分析这个项目"
}
```

响应：

```json
{
  "messageId": "message-1"
}
```

实时执行内容通过该会话的 SSE 连接接收。

### `POST /session/stop`

停止会话当前执行。

```json
{
  "id": "session-1"
}
```

后端中断模型请求，终止 `processes` 中的全部工具进程，并把状态恢复为 `idle`。

响应：

```json
{
  "status": "idle"
}
```

### `GET /session/events?id={sessionId}`

建立 SSE 连接并加入 `session.clients`。连接关闭后从 `clients` 移除。

当前只发送以下事件：

| event | data | 含义 |
| --- | --- | --- |
| `status` | `{ status }` | 会话状态改变。 |
| `message` | `{ message }` | 完整消息加入会话。 |
| `text-delta` | `{ messageId, text }` | 助手文本增量。 |
| `thinking-delta` | `{ messageId, thinking }` | 助手思考增量。 |
| `tool-call` | `{ messageId, toolCall }` | 工具调用已完整生成。 |
| `tool-result` | `{ messageId, toolResult }` | 工具执行完成或被拒绝。 |
| `error` | `{ message }` | 模型、工具或服务端错误。 |

当前阶段不提供事件 ID、断线补发或 resync。

## 暂不提供

- 工具审批接口。
- 历史回退接口。
- usage 和上下文统计接口。
- MCP、skills、附件和模型发现接口。
