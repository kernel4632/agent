# Store 结构

`store.js` 只定义并导出以下数据结构，不能写任何逻辑，也不能增加中间层级。

```text
store
    config
        provider
            api
            key
            models
        tools
    workspaces
        id
        path
        sessions
            id
            title
            lastActiveAt
    sessions
        id
        status
        messages
            id
            role
            content
                type
                text: { text }
                thinking: { thinking }
                tool_call: { toolCallId, toolName, input, status }
                tool_result: { toolCallId, output, isError }
        provider
        model
        processes
        abortController
        clients
        textOnlyCount
```

## 字段说明

- `config.provider.api`：模型 API 地址。
- `config.provider.key`：模型 API Key。
- `config.provider.models`：可使用的模型。
- `config.tools`：工具列表。
- `workspaces`：工作区数据。
- `workspaces.sessions`：工作区下的会话摘要。
- `sessions`：完整会话数据。
- `sessions.messages.content`：按产生顺序保存消息内容块。
- `sessions.processes`：正在运行的工具进程。
- `sessions.abortController`：当前执行的停止控制器。
- `sessions.clients`：监听当前会话的 SSE 客户端。
- `sessions.textOnlyCount`：连续没有调用工具的回复次数。

设计中不增加任何未在上图出现的字段或中间层级。
