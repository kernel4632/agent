# Store 结构

`store.js` 只定义并导出以下数据结构，不能写任何逻辑，也不能增加中间层级。

```text
store
    config
        provider
            api
            key
            models
    tools
        name
        description
        inputSchema
    workspaces
        id
        path
        sessions
            id
            title
            lastActiveAt
    sessions
        id
        status
        messages
            id
            role
            content
                type
                text: { text }
                thinking: { thinking }
                tool_call: { toolCallId, toolName, input, status }
                tool_result: { toolCallId, output, isError }
        provider
        model
        processes
        abortController
        clients
        textOnlyCount
```

## 字段说明

- `config.provider.api`：模型 API 地址。
- `config.provider.key`：模型 API Key。
- `config.provider.models`：可使用的模型。
- `tools`：每次启动扫描 `server/tools/*.js` 得到的工具列表，每项保存 `name`、`description` 和 `inputSchema`。
- 工具执行函数只保存在 `Tool` 指令的私有索引中，不进入 store，也不写入 `config.json`。
- 每次请求 LLM 时，只使用 `store.tools` 中的工具信息构建请求。
- `workspaces`：工作区数据。
- `workspaces.sessions`：工作区下的会话摘要。
- `sessions`：完整会话数据。
- `sessions.messages.content`：按产生顺序保存消息内容块。
- `sessions.processes`：正在运行的工具进程。
- `sessions.abortController`：当前执行的停止控制器。
- `sessions.clients`：监听当前会话的 SSE 客户端。
- `sessions.textOnlyCount`：连续没有调用工具的回复次数。

设计中不增加任何未在上图出现的字段或中间层级。
