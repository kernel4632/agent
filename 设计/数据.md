# Store 结构

`store.js` 只定义并导出以下数据结构，不能写任何逻辑，也不能增加中间层级。

```text
store
    config
        provider
            api
            key
            models
        prompts
            system
            tool
    tools
        [name]
            description
            parameters
    workspaces
        id
        path
        sessions
            id
            title
            lastActiveAt
    sessions
        [id]
            id
            status
            messages
                id
                role
                content
                    text: { type, text }
                    reasoning: { type, text }
                    tool-call: { type, toolCallId, toolName, input }
                    tool-result: { type, toolCallId, toolName, output }
            provider
            model
            abortController
            clients
            tools
```

## 字段说明

- `config.provider.api`：模型 API 地址。
- `config.provider.key`：模型 API Key。
- `config.provider.models`：可使用的模型。
- `config.prompts.system`：每轮模型请求使用的系统提示词。
- `config.prompts.tool`：连续两次纯文本回复后，下一轮临时加入的工具提醒。
- `tools`：每次启动扫描 `server/tools/*.js` 得到的 LLM 工具定义对象，以工具名为键，每项保存 `description` 和 `parameters`。
- 工具执行函数只保存在 `utils/Tool` 的私有索引中，不进入 store，也不写入 `config.json`。
- 每次请求 LLM 时，只使用 `store.tools` 中的工具信息构建请求。
- `workspaces`：工作区数据。
- `workspaces.sessions`：工作区下的会话摘要。
- `sessions`：按 session ID 保存已经按需加载的完整会话 KV 对象。
- `sessions.messages`：直接保存并传给 AI SDK 的 `ModelMessage[]`，项目只为每条持久化消息增加 `id`。
- `sessions.messages.content`：直接使用 AI SDK 的 `TextPart`、`ReasoningPart`、`ToolCallPart` 和 `ToolResultPart`，不维护第二套消息字段或转换层。
- `sessions.abortController`：当前执行的停止控制器。
- `sessions.clients`：监听当前会话的 SSE 客户端。
- `sessions.tools`：当前会话正在运行的 `Tool.execute()` execution 集合，只存在内存中。

设计中不增加任何未在上图出现的字段或中间层级。
