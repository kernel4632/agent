# 数据契约

本文是数据结构和枚举值的权威来源。其他设计文档与本文冲突时，以本文为准。

## 命名规则

所有缩写遵循 HOP 命名规范：缩写跟在普通单词后整体大写。统一使用 `workspaceID`、`sessionID`、`messageID`、`blockID`、`toolCallID`、`eventID` 和 `apiURL`。

对象自身的字段仍使用小写 `id`。例如消息对象使用 `id`，引用该消息时使用 `messageID`。

## 枚举

### 工具权限

`permission` 表示持久化的工具权限规则：

| 值 | 含义 |
| --- | --- |
| `allow` | 不询问，直接执行。 |
| `ask` | 等待用户决定。 |
| `deny` | 不询问，直接拒绝。 |

### 批准决定

`decision` 表示用户对一次待批准工具调用作出的决定：

| 值 | 含义 |
| --- | --- |
| `once` | 只允许当前工具调用。 |
| `always` | 允许当前工具调用，并把该工具的 `permission` 改为 `allow` 后保存配置。 |
| `reject` | 拒绝当前工具调用。 |

批准等待 30 分钟后仍没有决定时，按 `reject` 处理。超时只影响当前工具调用，不修改持久化权限。

### 会话状态

| 值 | 含义 |
| --- | --- |
| `idle` | 没有正在执行的 Agent 循环。 |
| `running` | 正在请求模型或执行工具。 |
| `waiting` | 至少一个工具调用正在等待用户批准。 |
| `retrying` | 模型请求失败，正在等待下一次重试。 |
| `error` | 遇到不可重试错误，执行已结束。 |

停止不是持久状态。停止完成后状态是 `idle`，反馈事件额外携带 `reason: "stopped"`。

### 内容块类型

| 值 | 含义 |
| --- | --- |
| `text` | 助手或用户的文本内容。 |
| `thinking` | 模型推理内容。 |
| `tool_call` | 模型发起的工具调用。 |
| `tool_result` | 工具调用结果。 |

## 全局 store

`server/store.js` 只定义并导出以下结构，不执行加载、保存或派生计算：

```js
store = {
  engine: {
    version: "0.1.0",
  },
  config: {},
  workspaces: [],
  sessions: new Map(),
}
```

| 字段 | 含义 | 持久化来源 |
| --- | --- | --- |
| `engine.version` | 当前服务版本。 | 随程序发布。 |
| `config` | 供应商、模型、工具权限和系统提示词。 | `.agent/config.json` |
| `workspaces` | 工作区及其会话摘要缓存。 | `.agent/workspace.json` |
| `sessions` | 按需加载的完整会话，键是 `sessionID`。 | `.agent/sessions/{sessionID}.json` |

## 配置

```js
config = {
  providers: [
    {
      id,
      name,
      isEnabled,
      apiURL,
      apiKey,
      models: [
        {
          id,
          name,
          contextLimit,
          capabilities,
          options,
        },
      ],
      options,
    },
  ],
  tools: {
    [toolName]: {
      permission,
    },
  },
  systemPrompt,
  defaultModel,
}
```

| 字段 | 含义 |
| --- | --- |
| `providers` | 模型供应商列表。 |
| `provider.id` | 供应商唯一 ID。 |
| `provider.name` | 用户可见名称。 |
| `provider.isEnabled` | 是否允许该供应商处理请求。 |
| `provider.apiURL` | 供应商 API 地址。 |
| `provider.apiKey` | 原始 API Key 或 `${ENV_NAME}` 环境变量占位符。配置接口原样返回。 |
| `provider.models` | 用户已添加的模型。 |
| `model.id` | 请求供应商时使用的模型 ID。 |
| `model.contextLimit` | 模型上下文 token 上限。 |
| `model.capabilities` | 模型支持的能力列表。 |
| `options` | 供应商或模型的自定义请求选项。 |
| `tools` | 按工具名称索引的权限规则。 |
| `systemPrompt` | 所有会话默认使用的系统提示词。 |
| `defaultModel` | 新会话默认模型 ID。 |

配置读取和修改都使用原始值，不进行脱敏。`${ENV_NAME}` 只在发起模型请求前解析，配置文件和配置接口仍保留占位符原文。

配置修改使用部分对象递归合并：普通对象继续合并，数组和基础值整体替换。

## 工作区

```js
workspace = {
  id,
  path,
  sessions: [
    {
      sessionID,
      title,
      lastActiveAt,
    },
  ],
}
```

`workspace.sessions` 是主页列表使用的派生缓存，不是会话数据的真相来源。Session 模块是会话摘要的唯一所有者：创建和更新时由 `Session.save()` 同步，删除时由 `Session.delete()` 移除。

## 会话

完整会话分为持久化数据和运行时数据。运行时数据加载时重新初始化，不写入 JSON。

```js
session = {
  id,
  workspaceID,
  title,
  lastActiveAt,
  model,
  status,
  messages,
  rolledBack,
  usage,
  runtime,
}
```

### 持久化字段

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| `id` | string | 会话唯一 ID。 |
| `workspaceID` | string | 所属工作区 ID。 |
| `title` | string | 会话标题。 |
| `lastActiveAt` | ISO 8601 string | 最后一次业务活动时间。 |
| `model` | string | 当前模型 ID。 |
| `status` | session status | 当前执行状态。进程重启时将未完成状态恢复为 `idle`。 |
| `messages` | message[] | 按时间排列的消息。 |
| `rolledBack` | rollback data \| null | 最近一次回退移除的内容，发送新消息后清空。 |
| `usage` | usage \| null | 最近一次完成的模型请求 usage。 |

### 运行时字段

```js
runtime = {
  listeners: new Set(),
  nextEventID: 1,
  events: [],
  runner: null,
  waits: new Map(),
  processes: new Set(),
}
```

| 字段 | 含义 |
| --- | --- |
| `listeners` | 当前订阅该会话 SSE 的连接。 |
| `nextEventID` | 下一条 SSE 事件使用的递增 ID。 |
| `events` | 最近 500 条 SSE 事件的环形缓冲，用于断线补发。 |
| `runner` | 当前 Agent 循环的 `AbortController`，没有执行时为 `null`。 |
| `waits` | 按 `toolCallID` 索引的批准等待对象。 |
| `processes` | 当前会话启动的所有工具进程引用。 |

运行时控制对象全部归属于对应 session，不在 store 根节点建立平行的运行时 Map。

## 消息

```js
message = {
  id,
  role,
  content,
  contentBlocks,
  timestamp,
}
```

| 字段 | 含义 |
| --- | --- |
| `id` | 会话内唯一的消息 ID。 |
| `role` | `user`、`assistant` 或 `tool`。 |
| `content` | 便于搜索和快速展示的纯文本汇总。 |
| `contentBlocks` | 按模型输出和工具执行顺序排列的内容块。 |
| `timestamp` | ISO 8601 创建时间。 |

回退直接使用 message 或 block 已有的 `id`，不再增加单独的回退标识。

## 内容块

每个内容块都有会话内唯一的 `id` 和 `type`：

```js
textBlock = { id, type: "text", text }
thinkingBlock = { id, type: "thinking", thinking }
toolCallBlock = { id, type: "tool_call", toolCallID, toolName, input, status }
toolResultBlock = { id, type: "tool_result", toolCallID, output, isError }
```

`toolCallBlock.status` 使用 `pending`、`waiting`、`running`、`completed`、`denied` 或 `error`。

## Usage

```js
usage = {
  inputTokens,
  outputTokens,
  totalTokens,
  contextLimit,
  percentage,
}
```

供应商返回 usage 时使用供应商数据；未返回时使用 token 估算。`percentage` 为 `totalTokens / contextLimit * 100`。

## 回退数据

```js
rolledBack = {
  source,
  targetID,
  removedMessages,
  changedMessage,
}
```

| 字段 | 含义 |
| --- | --- |
| `source` | `message` 或 `block`。 |
| `targetID` | 触发回退的 message ID 或 block ID。 |
| `removedMessages` | 从会话尾部完整移除的消息。 |
| `changedMessage` | block 回退时被截断内容块的消息原值；消息回退时为 `null`。 |

回退只修改对话历史，不撤销工具已经造成的文件或外部系统变化。

## 持久化时机

会话在以下时机保存：

- 用户消息加入后。
- 一次模型流完整结束后。
- 一轮工具结果全部收集后。
- 状态变化后。
- 回退或撤销回退后。

模型的每个 delta 不单独落盘。这样避免高频写文件；代价是进程崩溃时可能丢失当前尚未完成的助手消息。
