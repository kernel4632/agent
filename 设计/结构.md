# 项目结构

本文定义目标目录及每个模块的职责，不描述当前代码。后端实现应依照本文重构。

## 数据目录

默认数据目录是 `%USERPROFILE%/.agent`，可以通过 `AGENT_DATA_DIR` 修改。

```text
.agent/
  config.json              供应商、模型、工具权限和系统提示词
  workspace.json           工作区及会话摘要缓存
  mcp.json                 MCP 配置，契约待补
  sessions/                每个会话一个 JSON 文件
  skills/                  skill 文件，契约待补
  tools/                   用户自定义工具，契约待补
```

`commands/` 暂时平铺。虽然文件数超过 8 个，但任一合理子目录都不足 4 个文件；强行分层会违反 HOP 的最小文件夹规则并降低局部可读性。

## 服务端职责

| 文件 | 职责 |
| --- | --- |
| `commands/config.js` | 加载、读取、修改和保存配置。API Key 保持原值。 |
| `commands/workspace.js` | 加载工作区摘要，添加、修改、移除和列出工作区。 |
| `commands/session.js` | 加载、创建、读取、修改、删除和保存会话；维护会话摘要缓存。 |
| `commands/agent.js` | 接收用户消息、启动循环、停止执行；保留三次无工具调用退出规则。 |
| `commands/turn.js` | 完成一轮模型交互：构建上下文、请求模型、保存助手消息、执行工具。 |
| `commands/stream.js` | 把模型流片段按顺序写入助手消息内容块。 |
| `commands/tool.js` | 列出、查找、批准、并行执行和停止工具。所有同轮工具调用均并行，不做路径互斥。 |
| `commands/approval.js` | 处理拒绝、允许一次和始终允许，唤醒等待中的工具。 |
| `commands/history.js` | 按消息 ID 或内容块 ID 回退，以及撤销回退。 |
| `commands/context.js` | 构建模型上下文并执行上下文压缩。它含会话业务身份，因此不放入 utils。 |
| `watchers/session.js` | 接收指令显式提交的会话变化并统一发布 SSE；是服务端业务事件的唯一发布位置。 |
| `utils/id.js` | 生成无业务身份的唯一 ID。 |
| `utils/retry.js` | 提供可被停止信号打断的无限指数退避等待。没有重试次数上限。 |
| `utils/sse.js` | 编码和发送 SSE 帧，不读取或修改 store。 |
| `store.js` | 只定义并导出全局数据结构，不执行加载、保存或其他业务逻辑。 |
| `server.js` | 顺序加载数据，直接注册全部 Elysia 路由，统一返回错误，监听端口并处理进程退出。健康检查在这里直接读取 `store.engine.version`。 |

## 启动顺序

`server.js` 按以下顺序启动：

1. 调用 `Config.load()`，把 `config.json` 加载到 `store.config`。
2. 调用 `Workspace.load()`，把 `workspace.json` 加载到 `store.workspaces`。
3. 在当前文件直接注册 health、config、workspace、session 路由。
4. 监听 `4632` 端口。

`store.js` 不导出 `load()`。加载动作必须能从启动入口追踪到具体业务指令。

## 暂不设计

以下能力保留目录或界面入口，但本轮不定义实现契约：

- MCP 配置及运行。
- skill 发现与加载。
- 自定义工具加载协议。
- 工具易读名称和参数 schema 的来源。
- 供应商模型列表发现。
- 消息附件和多模态输入。
