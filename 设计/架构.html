Agent Server

五层架构 · 功能可插拔 · 工具可热插拔 · messages 唯一数据源

设计哲学

做减法
遇到问题不加代码修补，而是消除问题发生的条件。例如：删除中间保存，让 messages 永远完整配对，而不是加代码修复半成品。
没有特殊情况
所有设计都是通用的。ask 和 finish 走同一套工具协议，所有工具都过同一行审批函数，不为任何功能写 if-else。
messages 唯一数据源
UI 和模型共用同一份 messages。所有功能通过操作 messages 互相影响。不维护两份数据，不做同步。
工具完全可移植
工具只有声明和执行逻辑，输入输出协议固定：execute(input, signal) → { output, isError?, stop? }。不注入框架能力。
只有 idle 和 running
session 永远只有两个状态。不为 ask、审批、压缩等功能增加新状态。ask = stop 后正常 idle。审批 = running 期间原地等待。
代码只有声明和逻辑
不做输入校验，默认输入正确。基础设施交给库。依赖越方便越好，心智消耗最小。每行代码都有注释。

五层架构

入口层 唯一的 HTTP 服务入口，只做路由分发，不包含任何业务逻辑
server.js
启动 Elysia 应用，注册全部 REST 路由。每个路由只提取请求参数然后调用对应的 command 或 feature，自己不做任何数据处理。
启动顺序：扫描工具 → 加载配置 → 加载工作区 → 初始化会话目录。
退出时：停止所有运行中会话 → 关闭全部 SSE 连接 → 停止 HTTP 监听。
store.js
全局内存数据中心。四个字段：config（供应商 + 提示词 + 审批 + 上下文）、tools（LLM 工具定义）、workspaces（工作区 KV）、sessions（已加载会话缓存）。
只定义结构，不提供方法。所有读写由 commands 和 features 直接操作。
▼
业务指令层 纯业务逻辑：声明式调用引擎和工具，从 store 读数据、写结果、发 SSE 反馈
agent.js
接收用户消息后调用 Loop 引擎。回调里只做三件事：发 SSE、保存 Session、clone 消息。管理 send/stop/finish 生命周期。自己不实现循环。
Agent.send · Agent.stop
session.js
管理会话完整生命周期：创建、加载、修改、删除、保存。负责 SSE 连接管理和审批 gate 回答。每个会话的保存通过互斥锁串行。
Session.create · load · get · update · remove · save · listen · emit · answer
workspace.js
工作区 CRUD。工作区 = { id, path, sessions[] }，代表用户注册的一个本地项目目录。删除工作区只移除记录，不碰磁盘目录。
Workspace.load · list · add · remove · save
config.js
加载和合并配置：模型供应商（api/key/models/maxTokens）、提示词、审批模式、上下文压缩参数。并发修改通过互斥锁串行。
Config.load · get · update · save
tool.js
工具调度器。启动时扫描 tools/ 注册全部工具。运行时并行执行模型的工具调用。所有工具执行前过同一行审批函数，配置决定是否阻塞。图片 output 自动转 AI SDK image part。
load · list · run · stop
▼
功能层 独立功能模块，可直接访问 store 和 utils，组合出完整的业务能力
loop.js
Agent 循环引擎。每轮：Context.build 构建视图 → 检查 token 超阈值则 Summary.generate 压缩 → Retry + LLM 请求 → 工具执行 → 三次纯文本退出。直接从 store 读取 provider/prompts/tools/context 配置。
Loop.run
context.js
上下文构建。从完整 messages 拼接出发给模型的精简视图，同时累加 token 数。有摘要时：保留开头 3 条 + 摘要 + 摘要前 3 条 + 摘要后全部。剥掉 summary/usage 非标准字段。
Context.build → [built, tokens]
summary.js
摘要生成。接收 build 后的消息，取中间部分调 LLM 流式压缩为结构化摘要。返回带 summary:true 标记的 assistant 消息，push 进 messages 后下次 build 自动跳过已被覆盖的历史。
Summary.generate
title.js
标题生成。用用户第一条消息调 LLM 生成 ≤15 字短标题。生成后更新 workspace 摘要并通过 SSE 通知前端。前端在首次 send 后并行调用，不阻塞主对话。
Title.generate
▼
基础设施层 封装外部库和协议细节，全部与项目无关，可独立复用
llm.js
通过 AI SDK 请求 OpenAI-compatible 模型。流式返回文本、推理和工具调用。内置单轮超时，自动合并 abort 信号。
LLM.chat
sse.js
SSE 协议封装：帧编码、广播到多客户端、30 秒心跳保活、连接生命周期管理。
SSE.encode · send · broadcast · connect
tool.js
扫描工具目录并注册。执行时自动做 signal 检查、流式读取、错误捕获和返回值归一化（Stream/Object/String 三种返回）。
Tool.scan · definitions · execute
message.js
消息工厂。生成带唯一 ID 的 AI SDK 格式消息。
Message.id · user · assistant · tool
retry.js
无限重试 + 指数退避（上限 60 秒）。可被 AbortSignal 中断。根据 HTTP 状态码和网络错误码判断是否可重试。
Retry.run · wait
file.js
跨平台原子文件写入。基于 write-file-atomic，写入中途崩溃时旧文件不会损坏。
File.write
error.js
从任意 throw 值中安全提取错误消息字符串。
errorMessage()
▼
工具层 独立可插拔，与项目架构无关。放入文件自动注册，删除文件自动移除
file.js
文件读写列搜。读取时通过 magic bytes 自动识别图片（PNG/JPEG/GIF/WebP/BMP/TIFF/AVIF），图片返回 base64+MIME，文本返回 UTF-8。
file_read · file_write · file_list · file_search
edit.js
精确字符串替换。指定 old/new 文本，只改匹配部分。支持 replaceAll。
edit
shell.js
在指定绝对路径执行系统命令。基于 execa，跨平台 Shell 选择（Windows=PowerShell, Unix=sh），abort 时杀进程树。
shell
grep.js
正则内容搜索。基于 ripgrep，返回文件路径、行号和匹配文本。
grep
glob.js
glob 模式文件查找。支持 ** 递归、* 通配、{a,b} 选择。基于 fast-glob。
glob
web.js
获取公开网页。支持 text 和 markdown 格式。markdown 用 turndown 转换 HTML。
web
ask.js
向用户提问。返回 stop:true 退出循环，前端渲染选择框，用户选择后正常 send。对后端来说和 finish 完全一样。
ask
finish.js
模型声明任务完成。返回 stop:true 通知循环退出。
finish

数据结构

store.config
provider — 模型供应商：api 地址、key 密钥、models 可用模型列表、maxTokens 上下文窗口大小（触发压缩阈值）
prompts — 提示词：system 系统提示词、tool 连续纯文本后的工具提醒
approval — 审批：mode 模式（none/all/selected）、tools 需审批的工具名列表
context — 上下文压缩参数：head 保留开头消息数、tail 保留摘要前后消息数
store.sessions[id]
id status messages provider model — 持久化字段（保存到 JSON 文件）
abortController clients tools gates — 运行时字段（hydrate 初始化，不持久化）

messages 里的每条消息遵循 AI SDK 格式。额外字段：
usage（assistant 消息）— LLM 返回的 token 用量，前端展示用，build 时剥掉
summary（摘要消息）— true 标记，build 定位用，发送前剥掉
store.workspaces[id]
id — 工作区唯一 ID
path — 用户注册的本地项目绝对路径
sessions[] — 该工作区下的会话摘要数组，每项：{ id, title, lastActiveAt }

工具协议

工具定义与执行
tools/ 目录放入 .js 文件
→
启动时 Tool.scan 自动注册
→
模型调用
→
approve()
→
execute(input, signal)
→
{ output, isError?, stop? }
每个工具文件 default export 一个对象：{ name, description, parameters, execute }。
execute 只接收两个参数：模型传的参数对象 + AbortSignal。不注入任何框架能力。
返回三种形式：ReadableStream（流式输出）、{ output, isError?, stop? }（结构化结果）、string（纯文本）。
特殊返回值：stop:true 让循环退出（finish/ask）。output.image + output.mime 被框架转成 AI SDK image part。
