# 后端流程

字段结构以 [数据.md](数据.md) 为准，HTTP 和 SSE 格式以 [接口.md](接口.md) 为准。

## 架构主线

```text
前端请求
  → server.js 识别路由并调用指令
  → commands 读取和修改 store
  → commands 保存文件并通过 Session.emit 反馈 SSE
  → server.js 返回 HTTP 结果
```

`server.js` 不处理业务数据。`store.js` 不执行加载、保存或其他逻辑。

配置、工作区和会话自行序列化 JSON，再通过 `File.write(path, content)` 先写完新文件并替换旧文件，避免进程中断留下半份内容。

## 启动

1. `commands/tool.load()` 调用 `Tool.scan()` 扫描 `server/tools/*.js`，并写入 `store.tools`。
2. `Config.load()` 读取 `.agent/config.json`，补齐 `prompts.system` 和 `prompts.tool`；旧版 `tools` 字段自动移除。
3. `Workspace.load()` 读取 `.agent/workspace.json`。
4. `server.js` 直接注册全部 Elysia 路由。
5. 监听 `4632`。

## 配置

### `Config.get()`

返回完整 `store.config`，包括 key 原值和 prompts。

### `Config.update(partialConfig)`

分别合并部分 provider 和 prompts，保存 `config.json`，返回完整配置。

## 工作区

### `Workspace.add(path)`

创建 `{ id, path, sessions: [] }`，加入 `store.workspaces` 并保存。

### `Workspace.remove(id)`

工作区仍有会话时拒绝移除，避免会话失去工具工作目录。空工作区只移除记录并保存，不删除本地目录。

## 会话

### `Session.get(id)`

优先返回内存会话。未加载时读取 `sessions/{id}.json`，并初始化：

```js
abortController = null
clients = new Set()
```

### `Session.create(workspaceId, provider, model)`

创建完整 session，并在对应工作区加入 `{ id, title: "新对话", lastActiveAt }` 摘要，然后保存两个文件。

### `Session.update(id, title, provider, model)`

- title 修改工作区会话摘要。
- provider 和 model 修改完整 session。
- 每次修改更新摘要的 lastActiveAt。

### `Session.remove(id, Agent.stop)`

`server.js` 把 `Agent.stop` 作为停止指令传入。运行中先等待模型、工具和最终保存结束，再删除 session 文件、内存会话和工作区会话摘要。

### `Session.listen(id)`

建立 SSE 连接并加入 `session.clients`，断开后移除。

### `Session.emit(id, event, data)`

把事件发送给 `session.clients` 中全部连接。当前不缓存事件，也不补发。

### `Session.finish(session, controller, error)`

根据正常完成、用户停止或执行错误设置终态，保存 session，释放本轮 abortController，并发送最终 error 和 status 事件。

## 发送消息

### `Agent.send(id, content)`

1. 读取 session；状态不是 `idle` 时拒绝发送。
2. 创建 user message 并加入 messages。
3. 设置 `status = "running"`。
4. 创建 abortController。
5. 保存 session 并发送 message、status 事件。
6. 后台启动 `Agent.run(id)`。
7. 立即返回用户 messageId。

## Agent 循环

### `Agent.run(id)`

每轮执行：

1. 把 `session.messages` 作为 AI SDK `ModelMessage[]` 直接传给模型。
2. 从 `store.config.provider` 读取 api 和 key，从 `store.config.prompts.system` 读取系统提示词。
3. 向 session.model 发起流式请求。
4. 把 AI SDK `text`、`reasoning` 和 `tool-call` 内容块按顺序直接写入 assistant message.content。
5. 流式期间通过 Session.emit 发送增量。
6. 完成后保存 assistant message。
7. 有工具调用时通过 `commands/tool.run()` 全部并行执行。
8. 把 AI SDK `tool-result` 内容块组成 tool message 并保存，然后开始下一轮。

循环退出规则：

- `run()` 使用局部数字记录本轮连续纯文本次数，不写入 session。
- 有工具调用时计数归零，没有工具调用时计数加一。
- 第一次没有工具调用，继续下一轮。
- 第二次没有工具调用，下一轮加入 `store.config.prompts.tool` 临时工具提醒。
- 第三次没有工具调用，保留普通回复并结束。

临时提醒不写入 session.messages。

## 错误和重试

- 网络超时、限流和 5xx 使用指数退避无限重试，不限制次数。
- 单次模型请求默认 120 秒超时，超时后进入无限重试。
- 退避等待接收 session.abortController.signal，停止时立即中断。
- 不可重试错误设置 `status = "error"` 并发送 error 事件。
- 正常结束设置 `status = "idle"`。

## 工具

### `commands/tool.load(directory)`

每次应用启动调用 `Tool.scan(directory)` 扫描工具。返回的 LLM 定义对象直接进入 `store.tools`，执行函数只保留在 `utils/Tool` 内部。

### `commands/tool.list()`

返回 `store.tools` 的独立副本，直接交给 `LLM.chat()`，不再维护第二种工具列表格式。

### `commands/tool.run(id, toolCalls)`

所有工具调用通过 `Promise.all` 同时执行，不做路径互斥。每个 `Tool.execute()` execution 加入 `session.tools`，结束后移除；结果按原 toolCalls 顺序返回。

### `Tool.execute(name, input, options)`

- `name` 选择已扫描工具，`input` 只包含该工具自己的参数，`options.onOutput` 接收输出。
- 返回值只有 `result` 和 `abort()`；工具内部通过停止信号结束文件、网络或 Shell 操作。
- `path` 不是 Tool 通用选项，只是文件和 Shell 工具自己的参数；相对路径由 `commands/tool.js` 从会话工作区展开。
- 单个工具失败只产生 `isError: true` 的结果，不中断其他并行工具。

## 停止

### `Agent.stop(id)`

1. abort session.abortController。
2. 遍历 `session.tools`，对当前会话全部 execution 调用 `abort()` 并等待结束。
3. 清空 abortController。
4. 设置 `status = "idle"`。
5. 保存 session 并发送 status 事件。

重复停止空闲会话直接返回当前状态。
