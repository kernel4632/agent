# 后端流程

字段结构以 [数据.md](数据.md) 为准，HTTP 和 SSE 格式以 [接口.md](接口.md) 为准。

## 架构主线

```text
前端请求
  → server.js 识别路由并调用指令
  → commands 读取和修改 store
  → commands 保存文件并通过 Session.emit 反馈 SSE
  → server.js 返回 HTTP 结果
```

`server.js` 不处理业务数据。`store.js` 不执行加载、保存或其他逻辑。

## 启动

1. `Config.load()` 读取 `.agent/config.json`。
2. `Workspace.load()` 读取 `.agent/workspace.json`。
3. `server.js` 直接注册全部 Elysia 路由。
4. 监听 `4632`。

## 配置

### `Config.get()`

返回完整 `store.config`，包括 key 原值。

### `Config.update(partialConfig)`

把部分配置合并到 `store.config`，保存 `config.json`，返回完整配置。

## 工作区

### `Workspace.add(path)`

创建 `{ id, path, sessions: [] }`，加入 `store.workspaces` 并保存。

### `Workspace.remove(id)`

移除工作区记录并保存，不删除本地目录或会话文件。

## 会话

### `Session.get(id)`

优先返回内存会话。未加载时读取 `sessions/{id}.json`，并初始化：

```js
processes = new Set()
abortController = null
clients = new Set()
textOnlyCount = 0
```

### `Session.create(workspaceId, provider, model)`

创建完整 session，并在对应工作区加入 `{ id, title: "新对话", lastActiveAt }` 摘要，然后保存两个文件。

### `Session.update(id, title, provider, model)`

- title 修改工作区会话摘要。
- provider 和 model 修改完整 session。
- 每次修改更新摘要的 lastActiveAt。

### `Session.remove(id)`

运行中先停止，再删除 session 文件、内存会话和工作区会话摘要。

### `Session.listen(id)`

建立 SSE 连接并加入 `session.clients`，断开后移除。

### `Session.emit(id, event, data)`

把事件发送给 `session.clients` 中全部连接。当前不缓存事件，也不补发。

## 发送消息

### `Agent.send(id, content)`

1. 读取 session；状态不是 `idle` 时拒绝发送。
2. 创建 user message 并加入 messages。
3. 设置 `status = "running"` 和 `textOnlyCount = 0`。
4. 创建 abortController。
5. 保存 session 并发送 message、status 事件。
6. 后台启动 `Agent.run(id)`。
7. 立即返回用户 messageId。

## Agent 循环

### `Agent.run(id)`

每轮执行：

1. 使用 session.messages 构建模型上下文。
2. 从 `store.config.provider` 读取 api 和 key。
3. 向 session.model 发起流式请求。
4. 把 text、thinking 和 tool_call 按顺序写入 assistant message.content。
5. 流式期间通过 Session.emit 发送增量。
6. 完成后保存 assistant message。
7. 有工具调用时通过 `Tool.runAll()` 全部并行执行。
8. 把结果组成 tool message 并保存，然后开始下一轮。

循环退出规则：

- 有工具调用时，`textOnlyCount = 0`。
- 没有工具调用时，`textOnlyCount += 1`。
- 第一次没有工具调用，继续下一轮。
- 第二次没有工具调用，下一轮加入临时工具提醒。
- 第三次没有工具调用，保留普通回复并结束。

临时提醒不写入 session.messages。

## 错误和重试

- 网络超时、限流和 5xx 使用指数退避无限重试，不限制次数。
- 退避等待接收 session.abortController.signal，停止时立即中断。
- 不可重试错误设置 `status = "error"` 并发送 error 事件。
- 正常结束设置 `status = "idle"`。

## 工具

### `Tool.runAll(id, toolCalls)`

所有工具调用通过 `Promise.all` 同时执行，不做路径互斥。结果按原 toolCalls 顺序返回。

### `Tool.run(id, toolCall)`

- 根据 toolName 从 `config.tools` 列表读取发送给 LLM 的工具信息。
- 根据 toolName 调用 `tools/` 中对应的本地实现。
- 没有出现在 `config.tools` 列表中的工具直接生成错误结果。
- 工具进程开始时加入 session.processes，结束时移除。
- 单个工具失败只产生 `isError: true` 的结果，不中断其他并行工具。

## 停止

### `Agent.stop(id)`

1. abort session.abortController。
2. 并行终止 session.processes 中全部进程。
3. 清空 abortController 和 processes。
4. 设置 `status = "idle"`。
5. 保存 session 并发送 status 事件。

重复停止空闲会话直接返回当前状态。
