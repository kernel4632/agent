# 调用链

本文用于从入口快速追踪到指令、数据和反馈。详细行为见 [流程.md](流程.md)。

## 总览

```text
前端事件
  → server.js 中的 HTTP 路由
  → 业务 command
  → store 中的 config / workspaces / session
  → command 显式调用 session watcher 发布 SSE
  → route 返回 HTTP 结果
```

除了健康检查，每条业务链都由 `server.js` 中的路由调用明确的业务指令。健康检查直接读只读版本字段，不额外建立指令或路由文件。

## 健康检查

```text
GET /health
  → server.js
  → 读取 store.engine.version
  → 200 { status, version }
```

## 配置

```text
GET /config
  → server.js
  → Config.get()
  → 读取 store.config
  → 返回完整配置原值

PATCH /config
  → server.js
  → Config.update(body)
  → 合并 store.config
  → Config.save() → .agent/config.json
  → 返回完整配置原值
```

## 工作区

```text
GET /workspace
  → Workspace.list()
  → 读取 store.workspaces

POST /workspace
  → Workspace.add(path)
  → store.workspaces 增加工作区
  → 保存 workspace.json

PATCH /workspace
  → Workspace.update(workspaceID, fields)
  → 合并目标工作区
  → 保存 workspace.json

DELETE /workspace?workspaceID=...
  → Workspace.remove(workspaceID)
  → store.workspaces 移除工作区
  → 保存 workspace.json
```

## 会话数据

```text
GET /session?sessionID=...
  → Session.get(sessionID)
  → 命中 store.sessions 则直接返回
  → 未命中则读取 sessions/{sessionID}.json
  → 初始化 runtime 后写入 store.sessions

POST /session
  → Session.create(workspaceID)
  → store.sessions 增加会话
  → Session.save()
     → 写 session 文件
     → 更新工作区会话摘要
     → 写 workspace.json

PATCH /session
  → Session.update(sessionID, fields)
  → 合并目标 session
  → Session.save()

DELETE /session?sessionID=...
  → Session.delete(sessionID)
  → Agent.stop()（仅在未空闲时）
  → 关闭 listeners
  → 删除 session 文件和内存对象
  → 删除工作区会话摘要
```

## SSE 订阅

```text
GET /session/events?sessionID=...
  → Session.listen(sessionID, Last-Event-ID)
  → listener 加入 session.runtime.listeners
  → 有可补发事件：从 session.runtime.events 依次发送
  → 无法补发：发送 resync
  → 返回 SSE Stream
```

每个会话独立维护 listeners、nextEventID 和最近 500 条 events。不存在全局 connections Map。

## 发送消息

```text
POST /session/send
  → Agent.send(sessionID, content)
  → 创建 user message 和 text block
  → session.messages 增加消息
  → session.status = running
  → 清空 rolledBack
  → Session.save()
  → watcher 发布 message-start + status
  → 后台启动 Agent.run()
  → 202 { messageID }
```

## Agent 循环

```text
Agent.run(sessionID)
  │
  ├─ Turn.run(sessionID, reminder)
  │    ├─ Context.build()
  │    │    └─ watcher 发布 context
  │    ├─ 找供应商与模型
  │    ├─ 解析 ${ENV_NAME}
  │    ├─ watcher 发布 api-request started
  │    ├─ 发起流式模型请求
  │    │    └─ Stream.consume()
  │    │         ├─ 修改 assistant message 的 blocks
  │    │         └─ watcher 发布 delta / tool-call 事件
  │    ├─ 请求成功 → 保存 message 和 usage
  │    ├─ watcher 发布 api-request completed
  │    └─ 有工具调用时 → Tool.runAll()
  │                         ├─ 所有 Tool.run() 同时开始
  │                         ├─ allow → Tool.execute()
  │                         ├─ deny → 拒绝结果
  │                         └─ ask → Approval.wait()
  │                                      └─ POST /approval 唤醒
  │
  ├─ 工具结果要求停止 → 退出
  ├─ 有工具调用 → 未调用计数归零 → 下一轮
  ├─ 第 1 次无工具 → 下一轮
  ├─ 第 2 次无工具 → 下一轮加入临时工具提醒
  └─ 第 3 次无工具 → 保留普通回复并退出
```

## 无限重试

```text
模型请求出现可重试错误
  → session.status = retrying
  → watcher 发布 error { willRetry: true } + status
  → Retry.wait(attempt, runner.signal)
  → 等待结束后 status = running
  → 重试同一次请求
  → 不设置次数上限

POST /session/stop
  → abort runner.signal
  → Retry.wait 立即中断
  → Agent.run 退出
```

## 工具执行与批准

```text
Tool.runAll(toolCalls)
  → Promise.all(toolCalls.map(Tool.run))
  → 所有工具完全并行
  → 结果按原 toolCalls 顺序汇总
  → 创建 tool message
  → Session.save()
  → watcher 逐个发布 tool-result

permission = ask
  → Approval.wait(sessionID, toolCallID)
  → session.runtime.waits 增加等待
  → session.status = waiting
  → watcher 发布 approval-needed + status
  → 30 分钟无决定时自动 reject

POST /session/approval { decision: once }
  → Approval.once()
  → resolve("once")

POST /session/approval { decision: always }
  → Approval.always()
  → config.tools[toolName].permission = allow
  → Config.save()
  → resolve("always")

POST /session/approval { decision: reject }
  → Approval.reject()
  → resolve("reject")
```

等待全部结束后 session status 从 `waiting` 恢复为 `running`。

## 停止执行

```text
POST /session/stop
  → Agent.stop(sessionID)
  → abort session.runtime.runner
  → 所有 waits 按 reject 完成
  → Tool.abortAll() 并行停止全部 processes
  → 清理 runner / waits / processes
  → session.status = idle
  → Session.save()
  → watcher 发布 status { status: idle, reason: stopped }
```

## 历史回退

```text
POST /session/history { action: rollback-message, messageID }
  → History.rollbackMessage()
  → 截断目标用户消息及后续消息
  → 被移除内容写入 session.rolledBack
  → Session.save()
  → watcher 发布 history

POST /session/history { action: rollback-block, blockID }
  → History.rollbackBlock()
  → 截断目标 block、同消息后续 blocks 和后续 messages
  → 原消息与被移除消息写入 session.rolledBack
  → Session.save()
  → watcher 发布 history

POST /session/history { action: undo }
  → History.undo()
  → 从 rolledBack 恢复消息和 blocks
  → 清空 rolledBack
  → Session.save()
  → watcher 发布 history
```

回退不撤销工具已造成的文件修改或外部副作用。

## 追踪边界

从任一路由开始，业务数据追踪最多经过三个文件：

```text
server.js route → command → store
                            → 显式调用 watcher feedback
```

复杂执行由 `Agent → Turn → Stream/Tool` 显式组合。每个文件只处理一个业务主体，调用关系不通过事件总线、魔法字符串或全局临时 Map 隐式传递。
