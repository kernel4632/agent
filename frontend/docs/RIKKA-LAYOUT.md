# RikkaHub 布局改造计划

目标：先把界面改成 RikkaHub 的手机端布局骨架，再只对桌面端明显不自然的地方做自适应。功能、数据、命令层保持现状。

## 参考来源

RikkaHub 是 Kotlin + Jetpack Compose + Material 3 Expressive 的 Android LLM 客户端。

- 手机：`ModalNavigationDrawer`，抽屉默认关闭，由顶部菜单打开。
- 桌面：横向宽度 ≥ 1100dp 时换成 `PermanentNavigationDrawer`，抽屉常驻，顶部不再显示菜单按钮。
- 抽屉：宽 300dp，四周 8dp 内边距；顶部是用户、问候、常用动作、文件夹和会话列表；底部是助手/模型选择和工具入口。
- 会话页：透明顶部应用栏，标题+模型/供应商副标题；消息区；底部输入栏（bottomBar），不是悬浮在内容上的独立卡片。
- 设置：大标题顶部栏 + 返回；内容是按组排列的圆角卡片列表，不是左侧导航栏。
- 颜色：Material You 动态色；大面积使用 `surface` / `surfaceContainer` / `primaryContainer` / `onSurfaceVariant`；圆角较大。
- 图标：Hugeicons。

## 目标结构

```text
App
  ThemeProvider
    .rikka-app
      AppDrawer            手机可关闭抽屉 / 桌面常驻
      .rikka-main
        TopBar             菜单 / 标题 / 副标题 / 页面动作
        main
          DraftView        新对话空状态 + 输入栏
          SessionView      消息区 + 输入栏
          SettingsPage     设置首页 / 设置详情
      CommandPalette
      Toast
```

桌面端：

```text
┌──────────────┬─────────────────────────────────────┐
│ 300px drawer │ TopBar                              │
│ 用户/新建    ├─────────────────────────────────────┤
│ 搜索/工作区  │                                     │
│ 会话列表     │ 消息 / 空状态                       │
│              │                                     │
│ 模型/设置    │ Composer（底部，左右 8px）        │
└──────────────┴─────────────────────────────────────┘
```

手机端：抽屉是覆盖层，主内容始终从左边 0 开始；顶部栏左侧有菜单按钮；输入栏贴底并留安全区。

## 断点

- `>= 1100px` 且横向：抽屉常驻，顶部栏不显示菜单按钮。
- 其他尺寸：抽屉为模态覆盖层，默认关闭；点击菜单打开，点遮罩或选择会话后关闭。
- 输入栏和消息区宽度跟随 RikkaHub 的 `fillMaxSize`：占满主区，左右各 8px；消息列表内边距 16px。

## 现有数据怎么放

- `workspaces` → 抽屉文件夹胶囊栏；没有文件夹模型，所以一个工作区显示成一个胶囊。
- 会话摘要的 `updatedAt/createdAt` → 抽屉会话列表的日期分组和排序（修改时间 / 创建时间）。
- `store.config.activeModel` → 顶部栏模型副标题和新对话输入栏的模型选择；抽屉底部只显示助手身份。
- 设置页登记表 → 设置首页卡片；详情页继续用现有设置控件。
- 命令面板、Toast、快捷键、会话/设置命令保持不变。

## 视觉规则

- 直接用 Material 3 role token：`--md-sys-color-*`，在 `tokens.scss` 里映射成现有 `--la-*`，不新造一套颜色。
- 抽屉、卡片、输入栏使用 `surfaceContainer*` 和较大圆角；选中会话用 `secondaryContainer` 或 `surfaceContainerHighest`。
- 主按钮、发送按钮使用 `primary` / `onPrimary`；错误使用 `error`。
- 不引入新依赖；继续 Vue + SCSS + 现有 `ui/` 控件。
- 手机和桌面共用同一套 DOM，用 CSS 适配，不做两套页面。

## 实际结果

- 手机：抽屉默认收起，菜单或“打开会话抽屉”打开；主内容左边界 0；会话、设置、空对话都用同一套抽屉/顶部栏。
- 桌面：按 RikkaHub 的 `1100dp` 阈值恢复常驻抽屉；小于 1100 的横屏窗口使用模态抽屉。
- 抽屉：300px，50px 圆形用户头像、问候、常用动作、工作区文件夹胶囊和排序按钮、日期分组会话、助手选择和设置。
- 顶部栏：64px，手机有菜单，桌面隐藏菜单；标题 14px + 模型副标题 8px；标题可点击重命名；右侧只保留文件面板和新建对话，图标在列表和关闭之间切换。
- 输入栏：贴底、占满主区、20px 圆角、`surfaceContainerLow` 背景；底部左侧是模型和搜索，右侧是添加、语音、发送/停止，尺寸按 RikkaHub 的 40px 图标按钮和 30px 动作按钮。
- 设置页：设置首页分组卡片 → 修改后自动保存；详情只保留一个返回按钮，首页再按返回退出设置。
- 颜色：`--la-*` 映射到 `--md-sys-color-*`，使用 M3 surface/container/primary/error 角色；浅色和深色都检查过。
- 测试：构建通过，界面检查 34/34。

### [x] R5：Roo Code 式消息流与任意消息回退

> R6 已把这里的助手单列列表替换成 RikkaHub 气泡和独立步骤卡片；回退和草稿行为保留。

- 用户消息按 RikkaHub 放在右侧：头像、名字和 primaryContainer 气泡；助手消息在左侧，按 Roo Code 的单列列表展示。
- 助手流按 RikkaHub 组织：头像/模型标题行、紧凑的思考/工具步骤卡片、正文；步骤之间没有大块空白，只有 0-4px 间隔。展开高度、流式 shimmer、行淡入和操作按钮淡入都使用 CSS 过渡。
- 一条用户消息之后的连续助手消息（包括 agent-core 自动接续）合并成一个助手轮次；助手头像和名字只在轮首出现一次，后续思考、正文、工具和自动接续都归在这一轮里。
- 助手消息的复制/回退按行放在右侧操作区：优先思考行，其次正文行，只有工具时放最后一个工具行；每条助手消息只出现一次。
- 助手轮次内部是 Roo 式横向列表，不使用卡片：每行固定“图标 / 文本 / 右侧操作”；思考、工具、正文、错误和 token 都是普通行，轮次之间 12px，步骤之间 0-4px。
- 思考行在流式输出时显示 Rikka 式小预览：只保留最后约 600 字、72px 高、上下渐隐、自动跟到最新内容并带闪烁光标；输出结束后预览隐藏，点击整行文字展开完整推理。展开动作只有一个入口，右侧不再放第二个展开按钮，只保留不可点击的状态箭头。
- 用户块保留“回退到这条消息”，助手块新增“回退到这条回复”；回退弹窗标题跟着目标类型变化。
- 回退目标可以是任意用户或助手消息；后端接口原本就接受任意 `messageId`，前端只补了助手块入口和草稿处理。
- 回退到用户消息时恢复草稿正文；回退到助手回复时清空草稿，不把回复正文当成用户输入。
- 回退到助手回复后，文件恢复开关、撤销回退提示和运行中禁用继续保留。

### [x] R6：按 RikkaHub 源码重做主聊天页

- 消息列表左右对齐：用户消息右对齐，助手消息左对齐；头部是 28px 圆形头像、用户名或模型名。
- 用户气泡用 primaryContainer，助手气泡用 surfaceContainerHigh，24px 圆角，靠头像一侧 6px 尾角，10px 内边距。
- 思考过程和工具调用从正文气泡里拆出，变成独立圆角卡片；正文气泡只放 Markdown。
- 消息动作移到气泡下方，悬停显示复制、回退、分支。
- 抽屉会话行改成单行标题、44px 行高、8px 间距、日期标题 surfaceContainerLow + primary 粗体；增加修改时间/创建时间排序。
- 抽屉底部模型下拉改成助手选择器；顶部栏模型改到标题副标题，标题可点击重命名。
- 新对话页去掉大图标空状态，改成 RikkaHub 式空列表 + 底部输入栏。
- 输入栏、消息区跟随 RikkaHub 全宽布局；统一 Hugeicons 图标名和 18px 动作图标。

### [x] R7：RikkaHub 独有入口映射到现有数据

- 文件夹 → 工作区胶囊；排序 → 修改时间 / 创建时间。
- 助手管理 → 现有设置页；助手选择器继续显示 la 和当前模型。
- 收藏 → 浏览器本地消息收藏（localStorage），消息工具条有爱心，抽屉底部打开收藏列表。
- 统计 → 当前会话的用户/助手消息、思考、工具和 token 汇总。
- 备份 → 统计弹窗里的“导出会话”，下载服务端最新会话 JSON。
- TTS → 助手消息工具条的浏览器朗读，再次点击停止。
- 没有对应数据的媒体生成、翻译和全局备份没有伪造入口。

### [x] R8：设置页改成 RikkaHub 式自动保存和单一返回

- 停止输入约 600ms 后自动保存，不再有“保存设置”按钮和底部保存栏。
- 顶部栏只保留一个返回按钮：详情页回设置首页，首页回聊天页；不再同时显示返回和关闭。
- 自动保存失败时全局提示条也会显示在设置页上方，不再被设置页挡住。
- 设置首页分组改成“通用设置 / 模型与服务 / 数据设置”，大标题 28px、400 字重，和 RikkaHub 的大标题栏一致。
- 连续修改会排队保存，关闭时等待正在进行的自动保存，不会因为保存中而直接丢掉最后改动。

### [x] R9：对话框统一成 RikkaHub 的 Material 3 AlertDialog

- 所有 `Dialog` 按 Compose `AlertDialog(title, text, confirmButton, dismissButton)` 的结构排：标题、内容、底部动作，没有额外说明段或字段标题。
- 对话框宽度按内容收缩，范围 280–560px；28px 圆角、24px 内边距、`surfaceContainerHigh` 背景、32% 黑色遮罩。
- 标题 24px/32px、400 字重；正文 14px/20px；输入框是 56px 高的 M3 描边输入框，编辑标题时只显示标题、输入框和动作。
- 底部动作是 Material 3 TextButton：40px 高、至少 64px 宽、20px 圆角；删除动作和 RikkaHub 源码一样使用默认主色，不额外改成红色实心按钮。
- 删除供应商和 MCP 的提示改成“删除后会自动保存”，不再提到保存按钮。
- 收藏弹窗和统计弹窗不再自己写固定宽度，统一由对话框控制，避免内容被裁切。

### [x] R10：聊天输入框底部选项按 RikkaHub 重排

- 底部左侧依次是模型选择、联网搜索；有推理能力的模型才显示推理按钮。右侧依次是更多选项、语音输入、发送/停止。
- 模型选择改成底部弹层：拖拽条、搜索框、按供应商分组的模型卡片、当前模型勾选；切换会话模型走现有 `/session/model` 接口。
- 更多选项改成底部弹层：添加文本/代码文件、对话设置、切换执行模式；执行模式和自动批准不再占用输入框底部。
- 语音输入在浏览器支持 Web Speech 时显示麦克风，点击开始/停止，识别结果追加到输入框。
- 联网搜索没有后端服务时打开说明弹层，不伪造搜索开关。
- 顶部栏模型下拉框改成纯副标题文本，模型切换统一从输入框左下角的模型按钮进入。

## 仍和 RikkaHub 不同的地方

- 媒体生成、翻译、助手知识库和全局备份没有对应后端；其余入口已用工作区、设置、本地收藏、会话统计、导出和浏览器朗读映射。
- 抽屉顶部的更新卡和备份提醒卡没有显示；用户昵称暂时固定为 la，没有编辑昵称弹窗。
- 抽屉底部只放了助手、收藏、统计、设置四个圆形动作；“菜单”和全局助手管理没有对应功能，没有伪造。
- 顶部栏模型已经改成 RikkaHub 的纯副标题文本；模型切换统一放在输入框左下角。
- 输入栏没有真正的联网搜索服务和推理等级；搜索按钮打开说明弹层，推理按钮按模型能力隐藏。全屏编辑和快捷消息还没有做。
- 设置首页已按 RikkaHub 分组，但详情页仍用现有表单控件，没有逐项改成 RikkaHub 的列表项样式。
- 消息附件、消息编辑、重新生成、翻译、引用、分支选择器和上下文检查点没有对应数据；已支持复制、收藏、朗读、回退和分支。
- 抽屉里的原生 `details` 菜单继续保留，等对应组件库控件到位再换。
