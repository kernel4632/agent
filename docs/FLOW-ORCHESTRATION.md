# run_flow：后续计划（未实现）

> 状态：不做。当前 0.x 基座没有流程编排，也不在内置扩展的范围内。  
> 2026-11-20：正文按现状改过。旧稿里的 `server/tools/run_flow.js`、`server/flows/`、`frontend/src/components/flow/` 从未进入现在的 `backend/` / `web/`，那些路径已经不存在。

## 为什么现在不做

当前内置扩展只覆盖会话、设置、基础工具、权限、技能、任务清单、MCP 和自动标题。多步流程编排（依赖、并发、失败策略、图视图）会同时改工具协议、推送和界面，属于 fork 之后才值得加的能力。

`new_task` 或子智能体也还没有；需要时同样用扩展加入，不要改 agent-core 的循环。

## 以后如果要做

做成一个普通扩展，而不是写回本体：

- 后端：流程描述、就绪队列、取消和失败策略，结果通过 `ctx.push` 推给前端。
- 工具：一个零依赖工具文件，由模型或用户启动一次流程。
- 前端：用 `app.toolViews` 或一块面板画节点和状态，不要改 History 的基本结构。

抽成独立 npm 包要等这个扩展自己稳定、并且外部确实有复用需求之后再考虑。
