feat: 回退到工具调用这一级，并修好一个忽略规则漏洞

回退的粒度从"消息"下沉到"工具调用"。快照按 toolCallId 分组，所以能看到
每一次改过文件的工具调用，可以只退其中一次：某一步改坏了不用把整轮对话和
别的工具的成果一起丢掉。这是 roo code 和 opencode 的按消息回退都给不了的粒度。

新增两个接口：
- GET  /session/tools/:sessionId          这个会话里哪些工具调用改过文件
- POST /session/rollback/tool/:sessionId  退回指定那一次之前，files=false 只去记录

顺带挖出并修掉一个真实的保护漏洞：忽略规则的 matcher 一直用 basename: true
编译，picomatch 在这种模式下只拿文件名去比，于是规则里凡带 / 的都永远匹配不上——
内置的 **/.agent/**、**/.ssh/**、**/.aws/**、**/.gnupg/** 四条一条都没生效。
也就是说工具本来可以读到 agent 自己的数据目录（里面有 API Key 和全部会话）和
用户的 SSH 私钥。现在整条路径和文件名各比一次，两种规则都能命中。

同时把 config 传错类型的状态码从 500 改成 400（那是用户填错，不是后端坏了），
并修掉几处说错话的注释和过期的版本号示例。

新增 tests/rollback.test.js 盯住工具级回退和这个安全默认，utils.test.js 已经
接近 700 行，不再往里加。
