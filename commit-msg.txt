feat: 自动批准改成按类别开关（读取 / 写入 / 命令 / MCP）

roo code 的自动批准是细颗粒度、能实时调的。原来那个布尔总开关做不到
"读随便读、写还是问我"，所以改成四类分别开关。

- 新增 utils/tool-kind.js：工具分类的唯一来源。自动批准和 plan 模式都从
  这里读，加一个内置工具只改这一张表，不用去两处同步。
- autoApprove 从布尔改成 { read, write, command, mcp }。旧设置文件里的布尔
  读到时摊到每一类上，用户升级不会发现自己的设置丢了。
- 认不出类别的工具（用户自己放进 tools/ 的）没有"自动批准"这个选项，
  即使四类全开也照样要问——不能因为不知道它是什么就替用户放行。
- 自动批准在任务跑着的时候也能改：审批时是现读设置的，不用重建 Agent，
  所以不受 409 限制。用户看到模型在乱改文件时要能当场把"写入"关掉。
  模式和能力仍然要求任务停止，因为它们建在 Agent 上。
- 契约跟上：openapi.json 抽出 AutoApprove 组件（四处引用同一份），
  README 补上按类别的说明和实时生效的说明。

新增三条防漂移检查，都用探针确认过会失败：
- 每个内置工具都在分类表里有一行（漏登记时 → 1 fail）
- 自动批准的类别和代码里的类别是同一组（文档漂移时 → 1 fail）
- 任务跑着的时候也能改自动批准（改成要重建时 → 1 fail）

另外把 agent-core 适配测试里那条 plan 模式的检查修对了：原来是从筛选后的
工具表上算"哪些是写工具"，筛过之后本来就不在里面，等于什么都没查；改成从
完整的内置工具表上算。

后端 85 pass / 0 fail。
